# إدارة توصيل المطعم — المرحلة الرابعة 0.4.0

تحديث عملي مبني على النسخة التي نجح GitHub Actions في إنتاج APK منها.

## الجديد
- إشعار محلي مرتفع الأولوية في جهاز السائق عند وصول طلب جديد بعد فتح حساب السائق.
- طلب إذن الإشعارات في Android 13 وما بعده.
- تسجيل حالة السائق في `users/{uid}`:
  - `available: true` عند فتح شاشة السائق أو انتهاء الطلب.
  - `available: false` عند استلام الطلب أو بدء التوصيل.
- سجل للطلبات المسلّمة داخل واجهة المطعم.
- عدم إظهار زر إلغاء للطلبات المكتملة.
- استمرار البحث بالهاتف وحفظ العميل وإنشاء الطلب وفتح الملاحة.

## التحديث على GitHub
ارفع محتويات هذا المجلد فوق ملفات المشروع الموجودة، مع المحافظة على `app/google-services.json`، ثم نفّذ Commit. سيبدأ Workflow تلقائيًا.

## حساب السائق
في Firebase Authentication أنشئ حساب السائق. ثم في Firestore أنشئ:

`users/{UID}`

والحقل:

`role` = `driver` (string)

## ملاحظة الإشعارات
الإشعار في هذه المرحلة يعمل عندما يكون تطبيق السائق مفتوحًا أو يعمل وتصل لقطة Firestore جديدة. الإشعارات المغلقة بالكامل تحتاج Firebase Cloud Messaging وخادم إرسال/Cloud Function، وتُضاف في مرحلة لاحقة.
